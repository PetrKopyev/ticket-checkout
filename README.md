# Оформление билетов

Интерфейс покупки билетов на мероприятие на моковых данных (тестовое задание Sqoch, «Тест 01»).
React 19 + TypeScript + Vite + Tailwind 4, тесты на Vitest. Бэкенда нет.

## Запуск

```
npm install
npm run dev      # http://localhost:5173
npm test         # правила, форматирование и мок-API
npm run build    # проверка типов и сборка
npm run lint     # oxlint
```

Нужен Node 22.12+.

## Как это устроено

Три шага: участники → проверка → результат. На первом экране видны тарифы и цены участников,
на втором — состав заказа и email. Успешный результат оформлен как билет с номером заказа,
QR-кодом (`qrcode.react`) и событием; кнопка «Скачать билеты» открывает печать браузера
(там же «Сохранить как PDF»), на бумаге остаётся только билет.

- `src/rules.ts` — чистые функции цены, итога, валидации участника, email и заказа;
  `buildOrder` обрезает пробелы по краям имени и email, схлопывает пробелы в имени
  и делает первую букву заглавной.
- `src/api.mock.ts` — 10 моковых мест и `confirmOrder` с задержкой 400 мс;
  места перепроверяются в момент подтверждения.
- `src/event.ts` — название, дата и место события.
- `src/format.ts` — русские формы возраста и счётчика мест (`plural`).
- `src/types.ts` — участник, заказ, шаг.
- `src/App.tsx` — состояние заказа, переключение шагов и фокус на заголовке.
- `src/components/EventHeader.tsx` — афиша, тарифы и правило сопровождения детей.
- `src/components/StepIndicator.tsx` — три шага с успехом или ошибкой на результате.
- `src/components/ParticipantsStep.tsx` — форма участников, карточки с ценами и счётчик мест.
- `src/components/ReviewStep.tsx` — состав заказа и форма email.
- `src/components/ResultStep.tsx` — билет с QR и «Скачать билеты» при успехе
  или карточка ошибки с дальнейшими действиями.
- `src/components/OrderSummary.tsx` — строки участников и итог; `compact` для узкой колонки.
- `src/components/SubmitBar.tsx` — липкий мобильный итог с единственной submit-кнопкой формы.
- `src/components/CheckIcon.tsx` — галочка для шагов и билета.
- `src/components/ui.ts` — общие классы и форматирование цены.

Правила из задания:

- Полный билет 2000 ₽ (от 14 лет), детский 1000 ₽ (младше 14).
- От 1 до 4 участников; у каждого имя и возраст, один email на заказ.
- Ребёнок младше 14 допускается только с участником от 18 лет в том же заказе.
  Участник 14–17 лет платит полный билет, но сопровождающим не считается.

Допущения: число детей на одного взрослого не ограничено (в задании нет); возраст — целое от 0 до 120;
имя до 60 символов; одинаковые имена допустимы (тёзки); email проверяется шаблоном и ограничен 254 символами.
Мок проверяет только места — настоящий бэкенд должен повторять правила из `rules.ts`.

## Как показать «места закончились»

Внизу страницы есть демо-панель (на всех шагах), в ней видно, сколько мест сейчас:

1. Заполните заказ и дойдите до шага «Проверьте заказ».
2. Нажмите «Демо: кто-то купил билеты» (мест станет 0) или «Демо: осталось 1 место»
   (в заказе должно быть 2 и больше участников).
3. Нажмите «Подтвердить» — увидите «Места закончились» либо «Осталось мест: 1, а в заказе N»
   с кнопкой «Изменить состав».
4. «Сбросить демо» возвращает 10 мест.
